# 更新主在身旁網站

全程使用繁體中文，用白話簡短回報目前在做哪一步。使用者不一定懂程式。
工作目錄是網站 repo。網址：https://chengcheming-ai.github.io/zhu-zai-shen-pang/

## 不可違反

- 不更動 `C:\Users\cheng\Desktop\Youtube` 裡的檔案，只讀取。
- 音檔只能來自使用者自己的影片檔，不可從 YouTube 下載或抽取（違反 YouTube 政策）。
- 經文內容必須逐字取自信望愛站和合本，不可憑記憶、不可改字。
- 第 5 步使用者同意前，不可 commit 或 push。

## 1. 取得最新版本並同步

1. `git pull --ff-only`。失敗就停下，說明原因，不要強制處理。
2. `node scripts/sync-youtube.js`，讀取新歌並配經文（寫入 `catalog.js`）。
3. 找出這次要處理的歌：剛新增的歌，加上 `catalog.js` 裡尚未列入 `song-audio.js` 的歌。

GitHub 每週一、四也會自動同步，新歌可能已在第 1 點拉下來，所以不能只看第 2 點的輸出。

如果沒有要處理的歌、`git status` 也沒有待發布的變更：告訴使用者「YouTube 上沒有新歌（可能還沒公開或還沒讀到），網站已是最新」，然後結束。Shorts 與尚未公開的首播不會加入。

## 2. 檢查歌曲資料與經文

對每首要處理的歌，檢查 `catalog.js` 那一行：

- **歌名：** `zh`、`en` 是否正確分開。標題格式應為【中文歌名 English Title】；`en` 為空時，用影片標題判斷。不可自行翻譯或創作英文歌名，查不到就留空並回報。
- **片長：** `time` 為空時，從第 3 步的音檔或影片頁補上。
- **分類：** `theme` 是否符合歌曲。
- **經文：** 腳本只靠關鍵字配對，要真的判斷是否切合。用 `https://www.youtube.com/watch?v=<id>` 的影片說明（通常含歌詞）比對歌名與歌詞。不合適就先從 `scripts/verse-pool.json` 另選尚未使用的經文；都不合適才到信望愛站查和合本原文。同一節不要與其他歌重複。

## 3. 產生背景播放音檔

先確認工具存在，沒有才安裝（只裝在 repo 內，已被 git 忽略）：

```
npm install --prefix .tools ffmpeg-static
```

然後執行：

```
node scripts/build-song-audio.js "C:\Users\cheng\Desktop\Youtube"
```

讀輸出並處理：

- **找不到影片檔：** 列出歌名，說明要把影片放進 `Youtube` 資料夾（檔名與歌名相同）。詢問要等使用者放好後重跑，或先上線（這首暫時只有影片模式，手機無法背景播放）。
- **片長不符：** 代表可能配錯檔案或版本不同。不可發布這個音檔，先問使用者。
- **歌名用字不同：** 列入回報，請使用者確認。

## 4. 測試電腦版與手機版

背景執行 `node scripts/preview-server.js`（網址 http://localhost:8765/），用 Playwright 測試兩種尺寸：**電腦 1280×800**、**手機 390×844**。

兩種尺寸都要確認：

- 新歌出現在清單最上方，歌名、片長正確，播放時顯示對應經文。
- 按「背景播放」：自動開始播放並收成底部小播放列，進度前進，歌名正確，音檔沒有 404；點小播放列能回到完整播放區。
- 拖曳進度到結尾後，會自動接下一首。
- 切回「影片」：出現 YouTube 播放器（本機可能無法實際播放影片，以有載入播放器為準）。
- 頁面沒有水平捲動，主控台沒有錯誤。

各截一張圖並實際看過版面。

結束後關閉瀏覽器與預覽伺服器，清除測試產生的暫存檔。測試不通過就先修正；修不好就如實回報，不要發布。

電腦上測不出手機鎖螢幕時的實際行為，不可宣稱已驗證。

## 5. 確認後發布

用簡短表格列出每首歌的歌名、片長、分類、經文（節數＋內文），以及音檔狀態與測試結果。把 `git status` 裡這次會發布的其他變更也用白話說明。

接著用 AskUserQuestion 問一次是否發布到公開網站。

- **同意：** 確認 `git status` 只有預期的檔案後，`git add` 這些檔案、commit（訊息寫新歌歌名）、`git push`。
- **push 被權限機制拒絕：** 不要嘗試繞過，也不要自行取用憑證。給使用者一行可貼上執行的 `! git push`。
- **不同意：** 保留變更不發布，並告知下次點捷徑會接續。

## 6. 確認上線

push 後每 30 秒檢查一次，最多 5 分鐘：線上的 `song-audio.js` 含有新歌 id，且其中一個新音檔能取得（HTTP 200）。加上 `?t=<時間>` 避開快取。

最後回報結果和網址，並請使用者用手機按「背景播放」、鎖螢幕聽一次新歌。若逾時未生效，如實說明。
